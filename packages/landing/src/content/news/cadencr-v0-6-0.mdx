CadencR v0.6.0 is the release where the app starts to feel less like a UI around agent terminals and more like an **orchestration IDE for agent work**.

The main idea is simple: if agents are going to help with real projects, they need a better operating surface than a chat box. They need to see workspace context, coordinate with other sessions, work inside isolated project scopes, and leave enough visible state for a human to stay in control.

This release moves several big pieces in that direction: **CadencR-owned MCP tools for project and workspace orchestration**, a **much more capable editor**, **scheduled and pinned conversations**, **searchable long sessions**, **JSON-backed settings for automation**, and reliability fixes across worktrees, compaction, and provider-specific session behavior.

## Agent orchestration inside CadencR

The biggest structural change is the new **CadencR-owned project and workspace MCP orchestration layer**.

Agents can now work through CadencR's own understanding of the workspace instead of relying only on raw shell commands or disconnected context. The project and workspace MCP surfaces let agents inspect activity, list projects, search project context, follow conversation tails, compare relevant session history, and safely **message or spawn scoped sessions** from inside the active CadencR workspace.

That matters for multi-agent work. A session should be able to ask what else is happening, hand off follow-up work, or inspect another related conversation without turning the whole app into a pile of hidden terminals and ad hoc notes. CadencR v0.6.0 starts making that coordination explicit, visible, and scoped.

The desktop Settings UI now exposes this orchestration layer as part of the product instead of hiding it as backend plumbing. The goal is not to make agents magically autonomous. The goal is to give them better rails when you do ask them to coordinate.

## A real IDE-grade editor workspace

The editor also takes a major step forward in v0.6.0.

CadencR can now handle larger files more safely with **read-only large-file mode** and **hybrid lazy file-tree loading**. The editor gained git gutter markers, **LSP diagnostics and status**, **document symbols**, **workspace symbols**, **references**, **rename support**, formatting, better root resolution for monorepos, and multi-server language tooling for TypeScript, linters, and formatters.

This is the practical human side of agent work. Agents can make large changes, but you still need to inspect the diff, jump through code, check diagnostics, understand symbols, and make small corrections without leaving the workspace.

Version 0.6.0 makes that review loop faster. When an agent mentions a symbol, you can navigate it. When a file is huge, the app protects the session instead of freezing. When diagnostics matter, they appear inside the same surface where you are already reviewing the agent's work.

## Better ways to manage long-running conversations

Long conversations are where agent products usually start to fray. CadencR v0.6.0 adds several tools for keeping them manageable.

**Pinned conversations** now live in a dedicated global section above the project list, so important sessions stay reachable even after the sidebar fills up. **In-conversation search** brings `Cmd+F` / `Ctrl+F`, highlighted matches, keyboard navigation, and `Escape` to close, which makes long agent runs searchable like an IDE or browser page.

## Settings you can inspect and automate

CadencR settings are now moving into **JSON-backed global and project files**.

That means configuration becomes easier to inspect, diff, script, and modify from outside the app. It is a small-sounding change with a large workflow impact: teams and power users can reason about configuration as files instead of treating it as opaque application state buried in SQLite.

The existing settings APIs remain the compatibility layer for the app. Validation still matters, migrations still matter, and malformed or unsupported settings are surfaced as user-visible errors instead of being ignored silently. The important shift is that programmatic configuration changes now have a **first-class file-backed path**.

## Reliability fixes for worktrees, compaction, and providers

A release this large also includes a lot of unglamorous fixes that make daily work feel less surprising.

**Claude worktree sessions now preserve root-level Claude configuration, skills, commands, rules, and MCP settings** for subfolder projects, so skills available before entering a worktree remain available afterward. Worktree sessions are also more reliable: CadencR avoids reusing the project's main working tree, replays persisted setup output, and starts MCP-spawned worktree sessions more consistently.

**Compaction now has visible in-progress feedback across providers** instead of looking like a hung request. Claude background agents keep the parent conversation visibly active while they are still running. Branch switching for worktree-backed projects now tells the truth when a switch is deferred until the first message instead of implying the underlying worktree changed immediately.

Provider-specific behavior also got cleaned up: **Codex permission modes propagate more reliably**, OpenCode thinking effort is cleared when a model cannot use it, incompatible-model startup is safer, Claude API errors are surfaced, and pending steering prompts no longer leave conversations stuck at turn boundaries.
