## Move between tools

Open **Agent**, **Editor**, **Terminal**, **Git**, or **Browser** from the workspace. Panes can be split and resized, so a file or preview stays beside the conversation.

**Auto layout** is enabled by default. Opening a browser page or a file reference can arrange it beside the agent. It remembers pane sizes and respects manual layout changes. Use its undo action or turn it off for the conversation or workspace when you want to manage the arrangement yourself.

Keyboard bindings depend on focus: `Cmd/Ctrl+P` opens the model picker in the composer and file search in the editor. Use the [shortcuts reference](../shortcuts/) to see each scope.

## First-run setup

The onboarding flow has six steps: **Welcome**, **Detect CLIs**, **Choose folder**, **Agent & model**, **Preferences**, and **Get started**. It discovers your installed providers and lets you choose initial preferences. A project setup dialog can also set its accent and worktree behavior.

Replay onboarding from **Settings → About**. Provider-account authentication is handled by each provider's own CLI.

## A practical daily loop

1. Use **For me** to find pending requests, failures, and unread replies.
2. Open the conversation that needs attention.
3. Inspect the result in Editor, Browser, or Git.
4. Send a follow-up, answer a request, or review the next change.
5. Use **In progress** or **Agents** to supervise parallel work.

Before a new conversation's first prompt, its usage grid shows the last 30 days. Use it to inspect activity before starting another task.
