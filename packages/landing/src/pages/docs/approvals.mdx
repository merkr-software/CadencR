## Plan approval

A planning workflow can pause with a proposed plan. Review the plan, then approve it, request changes with feedback, or reject it. The plan-approval keyboard scope is active while that request is visible.

## Tool permission

A permission card shows the tool, command, or input requiring a decision. Available choices come from the provider: they can include allowing once, allowing future matching requests, allowing for the session, or denying.

Inspect the option's actual label before choosing it. A persistent allowance and a session-only allowance are not interchangeable. Multiple pending permissions remain separate requests.

You can also answer pending permissions and questions from their sidebar indicators without opening the whole conversation. **For me** gathers conversations that need attention across projects.

## Structured questions

The question drawer displays the provider's questions and options, with free-text input when supported. Use number keys for options, Enter to submit, and the question-navigation controls for a batch. The [shortcut tables](../shortcuts/) list the live question-drawer bindings.

## Collaboration and access modes

These are separate concepts: collaboration mode describes how the agent should work, while access mode describes the runtime's permissions. The composer only offers modes the provider supports.

| Provider            | Current behavior to understand                                                                                                                                                              |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Claude Code         | New conversations default to **Auto**; a model known not to support it falls back to **Accept Edits**. Plan and opt-in Bypass are available as supported by the runtime.                    |
| Codex               | Planning/default collaboration controls pair with its configured approval and sandbox policy. Opt-in Full Access changes that access boundary. Native profiles can supply runtime defaults. |
| Cursor              | Supported collaboration and access choices, including Auto Review, are reported by its integration. Some upstream question and tool details remain limited.                                 |
| OpenCode            | Build/Plan and other advertised controls come from its ACP session. Do not apply Claude-only modes to it.                                                                                   |
| Local ACP connector | Models, modes, permission choices, and resume behavior depend on the connector's live handshake.                                                                                            |

Manage provider access settings in **Settings → Providers**. Mode changes can apply to the next request or require a runtime restart depending on the provider.

A worktree separates a task's checkout from another checkout. It does **not** enforce a filesystem or network sandbox. Bypass or unrestricted access still follows the provider's actual policy.

## Stop or continue

Use Stop or the active conversation's stop binding to interrupt work. The workspace-wide stop command stops all running agents. A stopped conversation can be continued with a follow-up; stopping a delegated child is an interruption rather than a completed failure result.
