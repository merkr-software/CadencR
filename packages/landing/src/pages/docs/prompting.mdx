The prompt feature in CadencR is more than a text box. It is the main control surface for working with an agent: starting work, continuing a session, attaching context, and responding when the agent needs something from you.

## What the prompt feature is for

You will usually use the prompt bar to:

- start a new piece of work
- continue an existing session
- refine or redirect what the agent is doing
- attach extra context when the task needs it
- respond to questions, approvals, or permission requests

In other words, this is not just input. It is the main handoff point between you and the agent.

## What the prompt feature includes

Here are the main capabilities around the prompt bar:

| Feature             | How to reach it                                                                | Why it is useful                                                                |
| ------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------- |
| **Draft saving**    | Automatic — drafts persist per session                                         | Helpful when you switch context or come back later                              |
| **Prompt history**  | Up / down arrow from an empty prompt                                           | Useful when you repeat similar actions or want to resend a previous request     |
| **File mentions**   | Type `@` and start typing a path                                               | Makes it easier to point the agent at the right place                           |
| **Slash commands**  | Type `/` at the start of the prompt                                            | Speeds up common workflows without leaving the keyboard                         |
| **Attachments**     | Paste, drag and drop, or use the attach button                                 | Add images, PDFs, and provider-supported files without leaving the prompt       |
| **Send**            | <kbd>⌘ Enter</kbd>                                                             | Plain <kbd>Enter</kbd> inserts a newline so you can write multi-line prompts    |
| **Schedule send**   | Use the send split-button when a feature can schedule messages                 | Queue a message for later; it is sent while CadencR is running                  |
| **Stop**            | <kbd>Esc</kbd> inside the session, or <kbd>⌘ Esc</kbd> for every running agent | Keeps you in control when the agent is moving in the wrong direction            |
| **Model picker**    | <kbd>⌘ P</kbd>                                                                 | Switch model per-message without leaving the prompt bar                         |
| **Thinking effort** | <kbd>⌘ T</kbd>                                                                 | Cycle reasoning effort when the task is harder (or easier) than usual           |
| **Permission mode** | <Kbd><ShiftIcon /></Kbd> <Kbd>Tab</Kbd>                                        | Cycle between ask / accept-edits / bypass — pick the right amount of guardrails |

### Mentions and slash commands in detail

- **`@` mentions** open a file picker as you type. Pick a file (or a folder) and CadencR inlines the reference so the agent knows exactly what to read.
- **`/` slash commands** at the start of the prompt expose project-specific and built-in commands — pre-baked prompts your agent provider exposes. Arrow keys to pick, <kbd>Enter</kbd> or <kbd>Tab</kbd> to insert.
- **Attachments** support paste, drag-and-drop, and the attach button. Images show previews; non-image files show as removable file chips. CadencR filters accepted file types by the active provider and sends provider-aware payloads — for example, Codex receives PDFs as file references.

### Picking model, profile, and effort per message

CadencR stays provider-neutral: the model picker (<kbd>⌘ P</kbd>) lists whatever models your active provider profile exposes — Claude, Codex, OpenCode, or a custom model you added in **Settings → Runtime & Models**. When a provider supports multiple profiles, the session controls let you pick the profile for the next prompt without rebuilding the whole session. The thinking-effort cycle (<kbd>⌘ T</kbd>) toggles among the levels that model supports; unsupported effort settings are cleared instead of being sent to a model that cannot use them.

## What happens around the prompt while you work

The prompt feature also supports the back-and-forth that happens after you send something.

For example, the prompt area may become the place where you:

- send a message now or schedule it for later
- answer a question from the agent
- approve or reject a plan
- respond to a permission request
- continue from a paused state

That matters because the prompt feature is built for ongoing work, not just one-shot messages. It helps the session keep moving without making you jump to a completely different part of the app every time the agent needs input.

<DocCallout title="Why this matters" variant="note">
  The prompt feature is designed to keep the interaction close to the work itself. You can write,
  review, respond, and continue without constantly rebuilding context.
</DocCallout>

## When the prompt feature feels most useful

The prompt feature becomes especially helpful when:

- you are working across several sessions and want a consistent control surface
- you need to attach extra context, like files, PDFs, screenshots, or Browser page comments
- the agent needs follow-up input instead of a full restart
- you want the app to remember your draft or recent prompt flow
- you prefer to stay inside the same workspace instead of switching tools
