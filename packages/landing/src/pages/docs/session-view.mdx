## What this page is for

Session view is the close-up view of one agent session.

It helps you:

- follow what the agent is doing right now
- understand what already happened
- decide whether to nudge, redirect, or continue the work
- come back later without needing a memory palace

<DocCallout title="Good news" variant="tip">
  You do **not** need to read every token. Most of the time, you can scan for intent, progress, and
  blockers.
</DocCallout>

## How to read the session without getting lost

Think of the session as a work log, not a novel.

A good skim usually looks like this:

1. **Search first if you remember a word.** <kbd>⌘ F</kbd> / <kbd>Ctrl F</kbd> opens in-conversation search and jumps between matches.
2. **Start with the latest update.** See what the agent thinks it is doing now.
3. **Look for visible progress.** Check for completed steps, tool results, edits, or a clear next move.
4. **Watch for blockers.** Errors, repeated retries, confusion, or "I need input" moments are your cue to jump in.
5. **Only scroll back when needed.** Go upward if you want the reason behind a change, not because you owe the transcript your full devotion.

### What is worth paying attention to

| If you want to know...           | Look for...                                                               |
| -------------------------------- | ------------------------------------------------------------------------- |
| What the session is trying to do | The most recent assistant summary or prompt                               |
| Whether it is making progress    | New files, edits, completed steps, or a concise recap                     |
| Whether it is stuck              | Repeated attempts, errors, compaction status, or questions waiting on you |
| Where something was mentioned    | The in-conversation search bar and its match count                        |
| Whether you trust the direction  | Clear reasoning, sensible changes, and results that match your goal       |

## Approvals, permissions, and questions

Most sessions will pause occasionally and ask for input. Each prompt has its own keyboard scope so you can clear them without leaving the keyboard.

### Plan approval

When an agent finishes planning, an approval bar appears:

- <kbd>⌘ Y</kbd> — approve and let the agent execute
- <kbd>⌘ N</kbd> — request changes (leaves room for feedback before execution)
- <kbd>Esc</kbd> — reject the plan entirely

### Tool permission prompts

When an agent wants to run a tool that needs your say-so, Cadencr surfaces a permission card:

- <kbd>⌘ Y</kbd> — allow once
- <kbd>⌘ L</kbd> — allow for the rest of the session
- <kbd>⌘ N</kbd> — deny

If you prefer the agent to fly without these prompts inside a sandboxed worktree, the permission-mode cycle (<kbd><ShiftIcon /> Tab</kbd> in the prompt) and the “bypass permissions” settings in **Settings → Runtime & Models** are how you opt in deliberately.

### Multiple-choice questions

When the agent asks a multi-option question, the question drawer takes over the keyboard:

- <kbd>1</kbd>–<kbd>9</kbd> — pick an option by number
- <kbd>⌘ O</kbd> — toggle the **Other…** free-text answer
- <kbd>Enter</kbd> — submit and continue
- <kbd>←</kbd> / <kbd>→</kbd> — jump between questions in a multi-step batch

### Stopping a runaway

- <kbd>Esc</kbd> stops the current agent.
- <kbd>⌘ Esc</kbd> stops **every** running agent across the workspace — useful when something
  hot-loops or you want to bail before a costly tool call lands.
- <kbd>⌘ Enter</kbd> (when the prompt is unfocused) maximizes the session into a full-screen view;
  <kbd>
    ⌘ <ShiftIcon /> Z
  </kbd>
  collapses it again.
- <kbd>
    ⌘ <ShiftIcon /> S
  </kbd>
  re-enables auto-scroll if you scrolled up to read history and the stream kept moving.

## Ways to steer or continue the work

You are still in charge here. The agent is helping, not freelancing with your afternoon.

You can step in when you want to:

- **tighten the goal** — "Focus only on the docs page, not the sidebar"
- **change direction** — "Skip the refactor and just fix the bug"
- **add context** — "This needs to make sense for beginners"
- **resume later** — continue from the current thread instead of starting over from scratch

A few practical habits help a lot:

- give one clear instruction at a time when the session starts wobbling
- mention constraints plainly, like deadlines, file limits, or tone
- use <kbd>⌘ F</kbd> / <kbd>Ctrl F</kbd> before manually scanning a long session
- ask for a short summary if the session has become long
- start a new session when the goal has changed completely

<DocCallout title="When to interrupt" variant="note">
  Interrupt when the agent is stuck, drifting, or solving the wrong problem. Let it run when the
  direction is good and the updates are boring in a healthy way.
</DocCallout>

## When to stay here vs go back to the feature workspace

Use session view when you want to understand or steer **one** thread of work.

Use the feature workspace when you want the wider picture: files, related sessions, Git changes,
editor context, or the next thing to work on.

| Stay in session view when you need to... | Go back to feature workspace when you need to... |
| ---------------------------------------- | ------------------------------------------------ |
| follow one agent conversation            | compare multiple sessions                        |
| answer a question or give a correction   | browse files or inspect broader changes          |
| check whether the agent is blocked       | switch tools and work across the whole feature   |
| resume a paused thread                   | decide what to do next across the feature        |
