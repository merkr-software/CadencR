## The pieces of a workspace

| Part                             | What it holds                                               | What you do there                                              |
| -------------------------------- | ----------------------------------------------------------- | -------------------------------------------------------------- |
| Project                          | A registered folder, project preferences, and conversations | Choose the repository or folder you want to work on            |
| Conversation / feature workspace | One task, its agent history, and its working context        | Ask for work, inspect the result, and continue the same thread |
| Agent session                    | The provider runtime behind a conversation                  | Select a provider, model, profile, and supported controls      |
| Worktree                         | A Git checkout used by the task                             | Keep independent edits on separate branches and folders        |
| Panes                            | Agent, Editor, Terminal, Browser, and Git                   | Keep the conversation beside the evidence you are reviewing    |

The interface still uses **feature** in some controls. A feature can be a fix, review, investigation, documentation update, or another focused task.

## Start with one task

1. Register a project folder.
2. Create a conversation and describe the result you want.
3. Check the selected provider, model, and branch/worktree behavior before sending.
4. Inspect the files and Git diff, run checks, and answer any requests from the agent.
5. Commit or continue once you have reviewed the result.

New conversations start with the provider and model from your last accepted **manual** prompt across projects. An explicit conversation override still takes priority. Other controls depend on the provider and model you select.

## Work in parallel deliberately

Separate worktrees let independent agents edit different checkouts. You can also reuse a worktree when two conversations need to inspect the same uncommitted work. Reuse means they share files; it does not create another copy.

An agent can delegate through [MCP & orchestration](../mcp/). The sidebar shows related conversations, requests, and unread replies so you can follow the work across projects.

## Local work and remote access

Agents and workspace state run on your host machine. Optional [remote access](../remote-access/) pairs another device with that host. The host must remain running for agent work, schedules, and remote control.

A worktree organizes files. The provider's access mode controls permissions and sandboxing; a worktree itself does not restrict filesystem or network access.
