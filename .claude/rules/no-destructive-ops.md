**Never remove the production database.** Never delete, truncate, overwrite, replace, or `rm` anything in the production database directory: `~/.cadencr/database/` on macOS, `$XDG_DATA_HOME/cadencr/database/` on Linux (default `~/.local/share/cadencr/database/`). That covers `cadencr.db`, its `-wal`/`-shm` files and its `*.cadencr.backup.db` migration backups. `app_paths::database_path()` (Rust) and `resolveDatabasePath()` (Electron main) resolve this path.

**Test databases are disposable.** Delete them freely, and don't archive them: the dev DB (`packages/service/cadencr.local.db`), the clones in worktrees, QA or scratch `--db-path` files, and their backups. Never start a service on a copy of a database that holds real schedules and agents, though: it fires the schedules and reaps the agents of the live service. Point `--db-path` at a fresh file instead.

**Never roll back changes without explicit user approval.** Do not `git reset`, `git revert`, `git checkout --` / `git restore`, or otherwise undo committed or uncommitted work unless the user has replied with exactly this phrase: `I approve this rollback`. Paraphrases, implied consent, "go ahead", or approving a related plan do not count.
