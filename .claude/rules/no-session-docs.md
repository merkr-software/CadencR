Only commit documentation that stays true and useful after the task ends: reference, contracts, runbooks, decisions (`docs/adr/`). QA reports, qualification evidence, investigation notes, delivery plans, progress checkpoints and handoffs belong in the PR description, the issue or the final reply, never in a tracked file. No dated report files (`*_2026-10-24.md`), no "the user authorized…" or "current checkpoint" sections; when work lands, update the reference doc to the new state instead of appending history — git keeps the history.
