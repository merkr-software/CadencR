Never swallow errors silently — no empty catch blocks, no `catch (_) {}`, no log-only handling. Surface every error to the user: a toast or inline message on the frontend, a meaningful error response on the backend.

In the Rust service, `clippy::let_underscore_must_use` and `clippy::unused_result_ok` are denied outside tests (`packages/service/src/lib.rs`), so `let _ = fallible();` does not compile. Drop a result on purpose only through a named helper in `shared::discard` (`ignore_closed()` / `send_ignore_closed()` for a send whose receiver hung up, `keep_first()` for a `OnceLock` set once, `cleanup()` for best-effort teardown) or an `#[expect(clippy::let_underscore_must_use, reason = "...")]` that says why. Clippy cannot see `.ok()`, `unwrap_or_default()` or `if let Ok` on a `Result`: treat "not found" as empty only for a real `NotFound`, and return or report every other error.
